🏗️ Architecture du parseur EVA v1
1. Structure générale
Le parseur est une classe Parseur qui contient :

python
class Parseur:
    tokens: list[Token]      # la liste complète produite par le lexer
    position: int            # le curseur (index du token courant)
Pourquoi une classe et pas des fonctions ? Parce que le curseur est un état partagé. Une classe le garde proprement. Des fonctions auraient besoin de le passer en paramètre à chaque appel — vite pénible.

2. Méthodes utilitaires (à écrire en premier)
Ces méthodes sont utilisées partout. Ce sont tes outils de base.

Méthode	Rôle
token_courant()	Retourne le token à la position actuelle
token_suivant()	Retourne le token à position + 1 (sans avancer)
avancer()	Incrémente la position de 1
verifier(type_, valeur=None)	Vérifie que le token courant est du type attendu (et éventuellement de la bonne valeur). Lève une erreur sinon
consommer(type_, valeur=None)	Vérifie puis avance
est_fin_bloc()	Retourne True si le token courant est fin, fin si, fin cas, fin pour, fin tant que, sinon, jusqu'a
erreur(message)	Lève une erreur de parsing avec la ligne du token courant
Ces 8 méthodes sont la fondation. Une fois qu'elles existent, le reste s'écrit facilement.

Niveau 5 — Expressions
Les expressions sont l'endroit où on descend et remonte la hiérarchie de priorité. Une méthode par niveau.

Méthode	Règle	Priorité
parse_expression()	point d'entrée	—
parse_ou_expr()	{ ou }	7 (faible)

Ces 10 méthodes forment la chaîne d'expression. Chacune appelle la suivante, et remonte en testant les opérateurs de son niveau.

4. Ordre d'écriture recommandé
N'écris pas dans l'ordre d'appel (racine d'abord). Écris du bas vers le haut :

Les utilitaires (token_courant, avancer, consommer…). Sans eux, rien ne marche.

Les primaires (parse_primaire). C'est la base des expressions.

La chaîne d'expressions (parse_unaire → parse_puissance → … → parse_ou_expr). Tu la construis en remontant.

Les instructions simples (parse_affectation, parse_ecrire, parse_lire, parse_retourne, parse_appel_instruction).

Les instructions composées (parse_si, parse_cas, parse_pour, parse_tant_que, parse_repeter).

Les déclarations (parse_declaration_variable, etc.).

La structure (parse_fonction, parse_procedure, parse_algorithme).

La racine (parse_programme).

Pourquoi cet ordre ? Parce que chaque fonction n'appelle que des fonctions déjà écrites. Tu ne te retrouves jamais avec un appel vers du vide. C'est plus facile à tester au fur et à mesure.

5. Les pièges classiques
Piège 1 — Dispatch sur identifiant
Quand tu vois un identifiant, tu ne sais pas encore si c'est :

une affectation (x ← 5),

un appel d'instruction (afficher(...)),

une affectation à une case (T(i) ← 5).

Solution : regarde le token suivant :

text
identifiant + ←               → affectation simple
identifiant + ( ... ) + ←     → affectation à une case (le ( est plus loin)
identifiant + ( ... )         → appel d'instruction
Tu peux faire ça avec token_suivant() sans avancer.

Piège 2 — Fin de bloc
parse_instructions() doit s'arrêter sur plusieurs tokens différents :

fin (fin de l'algorithme)

fin si

fin cas

fin pour

fin tant que

sinon (dans un Si)

jusqu'a (dans un Repeter)

Solution : une méthode est_fin_bloc() qui teste tous ces cas. La boucle de parse_instructions() s'arrête dès qu'elle en voit un.

Piège 3 — Séparation par ligne
Tu as décidé : une instruction par ligne. À la fin de chaque parse_instruction(), tu dois vérifier que le token courant est sur une ligne différente — ou est un marqueur de fin de bloc.

Solution : au début de parse_instruction(), mémorise la ligne. À la fin, compare.

python
ligne_debut = self.token_courant()["ligne"]
# ... parsing ...
if self.token_courant()["ligne"] == ligne_debut and not self.est_fin_bloc():
    self.erreur("Deux instructions sur la même ligne")
Piège 4 — Descente/remontée d'expressions
Le point le plus subtil. Chaque méthode de la chaîne fait :

python
gauche = methode_niveau_suivant()
while token_courant est un operateur de ce niveau:
    operateur = consommer()
    droite = methode_niveau_suivant()
    gauche = OperationBinaire(operateur, gauche, droite)
return gauche
Exemple : parse_additif appelle parse_multiplicatif, puis tant qu'il voit + ou -, il construit des OperationBinaire("+", gauche, droite).

C'est ce qui fait que 2 + 3 * 4 devient 2 + (3 * 4) : quand parse_additif demande la partie droite à parse_multiplicatif, celui-ci voit 3 * 4 et le consomme avant de rendre la main.

Piège 5 — parse_puissance à droite
^ est associatif à droite : 2^3^2 = 2^(3^2).

Solution : dans parse_puissance, l'appel récursif se fait sur parse_puissance elle-même, pas sur parse_unaire :

python
def parse_puissance(self):
    gauche = self.parse_unaire()
    if token_courant == "^":
        self.consommer("^")
        droite = self.parse_puissance()   # ← récursion sur soi-même
        return OperationBinaire("^", gauche, droite)
    return gauche
Piège 6 — Cible d'affectation
T(i) ← 5 — la cible contient un appel. Tu vas produire AppelFonction("T", [i]) (décision 7.1). Ce sera Affectation(cible=AppelFonction(...), valeur=...).

Pas de piège, mais sois conscient que parse_cible() ressemble à parse_primaire(). Tu peux réutiliser cette dernière.

Piège 7 — Cas multi-instructions
Dans Cas, une branche peut contenir Debut … Fin. Tu dois aplatir : le Debut/Fin ne produit pas de nœud, juste une liste d'instructions plus longue.

Solution : dans parse_branche_cas, si tu vois debut après le :, tu appelles parse_instructions() et tu consommes fin. Sinon, tu appelles parse_instruction() une seule fois.

6. Récapitulatif
Total : environ 40 méthodes à écrire.

Répartition :

8 utilitaires

2 racine/structure

3 fonctions/procédures

6 déclarations

13 instructions

10 expressions

Ordre : du bas vers le haut.

Trois méthodes critiques à soigner particulièrement :

parse_instruction() — le dispatch.

parse_instructions() — la boucle avec fin de bloc.

parse_primaire() — la descente d'expression.

Trois pièges majeurs :

Dispatch sur identifiant (regarder le token suivant).

Fin de bloc multiple (une seule méthode est_fin_bloc()).

Associativité à droite pour ^.
